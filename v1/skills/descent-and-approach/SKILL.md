# Descent and approach

Use `fly-the-airplane` for how the tools work. Read the `descent` and `approach` checklist sections (`read_checklist` with `category`) and mark items as you confirm them. If you start close to the airport with the autopilot already flying, look first (`assess-flight-state`) and do not change what is already right. Do not press `lnav` or `vnav` when the FMC has no route.

## Descent

- Before top of descent, confirm the arrival and the approach, then select the permitted lower altitude on the MCP. A VNAV descent cannot begin normally while the MCP stays at the cruise altitude. Monitor path and speed; manage drag with `speedbrake` value 2 when necessary.
- Do not repeatedly press `altitude-intervention` or `speed-intervention`: they remove restrictions. If VNAV is unavailable (a stale CDU `NAV DATA OUT OF DATE` can hold cruise even with a lower MCP altitude), deliberately use `lvl-chg` or `v-s` with a verified altitude target and speed, then recover VNAV when suitable. Watch the PROG `TO T/D`.
- A short leg needs an early descent: check the path against the altitude you need at the final approach fix and be at about 160 kt before it. Do not let the speed ride up.
- Altimeter: `cockpit_altimeter` `std` at the transition level; at the transition altitude on descent `set-altimeter` with the QNH in inHg (`weather.qnh-in-hg`), then check `altimeter.setting` (the knob is clicked, so it takes a moment).
- Pressurization landing altitude: read `landing-altitude` in `hydraulics-and-air` (feet) and compare it with the destination field elevation from the chart; the cabin altitude is a different reading. `flight-altitude` is the selected FLT ALT (cruise altitude), changed with `flight-altitude-pressurization-up` / `-down` in 500 ft steps. Correct it with one call of `cockpit_hydraulics_and_air` `set-landing-altitude` (destination elevation in feet, multiples of 50; it turns the knob itself, so do not press `landing-altitude-pressurization-up` / `-down` repeatedly), then read `landing-altitude` back.
- Check the destination weather and choose a runway compatible with it, the available procedures and the autoland capability. Take the ILS frequency, identifier, magnetic course, intercept altitude, minima and missed approach from the chart. Do not invent them.
- Review warnings and system annunciators before intercept: read `fire-and-emergency` and the relevant system groups, not just the flight instruments and FMA. Use a documented recall control only if the tool schema exposes it; a master-caution reset is not a substitute for recall. Identify and handle active faults through the appropriate procedure, then read back. If recall or its feedback is unavailable, report that limitation and leave the recall item unconfirmed; continue separately verified items.

## ILS setup

- Tune and identify with `cockpit_radios_and_ils`: `set-nav-1-standby-frequency` (MHz), `nav-1-swap`, `set-nav-1-course` to the inbound course; the same for Nav 2. Verify `radios-and-ils.nav-1-frequency`, `nav-1-ident` (it must match the chart), `nav-1-course`, then `nav-1-localizer` and `nav-1-glideslope` (dots), `nav-1-dme` and `nav-1-glideslope-flag`.
- The localizer is receivable only on the approach side: an empty ident away from the final course is not a reason to scan frequencies. If it stays empty on the extended centreline within range, read the chart again.
- The localizer and glideslope appear only near the final course and within about 25 nm of the runway. An empty ident, `nav-1-localizer` 0.0 and `nav-1-glideslope-flag` 1 farther out or off the course are normal, not a fault. Do not stop the flight because of them: navigate with the FMC (`LEGS`, PROG `DTG`) and check the radio again once you are established on the final course.
- `height-agl` is the height above the terrain directly below, not above the runway. Over high ground it is smaller than altitude minus the field elevation. Use altitude (QNH) against the chart altitudes, and `height-agl` only near the field.
- A radio course may not set (the reading stays 0) and `nav-1-dme` may not track distance. Read the course back; if it will not set, treat the intercept as suspect and watch the localizer dots. Use the FMC PROG `DTG` or `latitude` / `longitude` for distance.
- Read the CDU APPROACH REF page (`init-ref`, then the displayed index/line-select keys if needed). Apply the CDU handling rules in `fmc-setup` without replaying ground setup: `cdu-type` appends text, an error message can hide the previous entry, and `clr` removes one character at a time. Before every new entry, clear the message and remaining text and read `fmc-cdu.scratchpad` until it is empty. After typing, verify the exact text before pressing the line-select key; after rejection, clear fully rather than appending another candidate.
- If APPROACH REF gross weight is blank, use current `takeoff-data.gross-weight` (kg) and the FMC's displayed/documented units. For thousands of pounds, convert kg × 2.2046 / 1000; do not enter whole pounds or kilograms into that field. Verify the accepted weight, select the landing flap/VREF from the resulting table, and read back the selected FLAP/SPD. Determine the weight-based target speed and correction before capture, then verify the MCP selection. If the FMC still rejects a correctly formatted entry from an empty scratchpad, report it; use a documented performance table at the current landing weight if available, otherwise discontinue the approach rather than guess. Do not mark the FMC entry complete when using a fallback.
- Set minimums using the chart datum: BARO takes the decision altitude AMSL, not the parenthesised height above the threshold; RADIO takes the published radio height when applicable. Check the tool's range before entry and verify both mode and value through available readings or documented state feedback. If the correct BARO altitude exceeds the tool range, report the limitation and monitor the published QNH altitude explicitly; do not substitute the chart's parenthesised height in BARO, switch to RADIO without a published applicable radio minimum, or mark the setting confirmed. If safe minima monitoring or the required visual references cannot be assured, go around. Missing feedback must not block unrelated checklist marks.
- Set and verify landing lights for final even when taking over below 10,000 ft; starting below a checklist's altitude trigger does not remove the required approach configuration. Set and verify the passenger signs and autobrake for the actual conditions.

## Intercept and configure

- Plan the join before descending: the final course starts on the extended centreline, about 10 to 15 nm out, with the aircraft below the glideslope altitude for that distance (field elevation plus about 320 ft per nm) and at about 160 to 180 kt. Arriving at 8 nm at 5,000 ft and 200 kt is too high and too fast: turn away and re-join from the correct side; do not try to capture from above.
- Keep the pattern tight around the field. Do not fly tens of nautical miles away from the centreline and back; it costs time and altitude and leaves the radios unusable.
- Establish above/below from geometry before changing anything: compare QNH altitude with threshold elevation plus about 320 ft per NM **to the threshold**, or the selected chart's glidepath table with its stated DME reference. Do not substitute CB DME, ICB DME and threshold distance for each other.
- With a valid identified ILS, negative `nav-1-glideslope` is below the path and positive is above; cross-check with geometry. A steady ±2.5 dots is a full-scale deviation, not proof that the receiver is frozen. Check whether DME and position change before declaring a distance fault.
- Capture **from below**: hold the permitted intercept altitude until the path reaches it. `ALT HOLD` active with `G/S` armed is normal while below the beam; lowering the MCP altitude alone does not start a descent. Estimate capture distance as (altitude minus threshold elevation) / 320, monitor progress toward it and configure meanwhile. Do not descend by hand or go around merely because the armed mode has not yet captured outside that distance.
- Slow down early so that gear, landing flaps and the landing speed are set before the glideslope. The autothrottle holds the selected speed, so use `set-speed` in steps and extend the flaps within their limits (see `landing`). Use `speedbrake` value 2 for drag and arm it (value 1) for landing.
- Select `app` once when properly positioned: ident matches, localizer within about two dots, on the final course and below the path. Read the FMA first; do not press APP again if already armed/captured. Judge a `verified: false` result by the resulting modes, not button feedback alone. Do not swap a correctly identified ILS off frequency to reset guidance.
- Verify LOC/G/S armed, then captured (`fma-roll` `VOR/LOC`, `fma-pitch` `G/S`) with near-centred deviations and a sustained descent consistent with the chart. A G/S label while level or climbing far below the beam is not a verified coupled final: do not engage the second CMD or raise the MCP on that label alone. Report unknown FMA codes without guessing their meaning; if actual guidance cannot be confirmed safely, follow `go-around`. From verified capture follow `ils-final-hands-off`, then `landing`.
- If the approach is not stable by about 1000 ft AGL, or guidance is lost, follow `go-around`.

## RNAV approach instead

Follow the aircraft's supported procedure: LNAV/VNAV final guidance shows **LNAV and VNAV PTH**; supported IAN guidance uses `app` with **FAC and G/P**. Identify which system this airplane supports first. An RNAV vertical path does not establish autoland capability: plan a manual landing unless the installed system explicitly supports it.
